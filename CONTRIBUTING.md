# Участие в Nimbus

[← На главную](README.md) · [Настроить окружение](docs/development.md) · [Архитектура](docs/architecture.md)

Помочь можно кодом, переводом, уточнением инструкции или воспроизводимым
сообщением об ошибке. Особенно полезны улучшения обработки медиа,
доступности, интерфейса и поддержки платформ.

## Сообщить об ошибке или предложить идею

Сначала проверьте [существующие issues](https://github.com/muted-team/nimbus/issues)
и [помощь с частыми проблемами](ИНСТРУКЦИЯ.md#troubleshooting). Если подходящего
обсуждения нет, [выберите шаблон](https://github.com/muted-team/nimbus/issues/new/choose).

Для ошибки нужны версия Nimbus, система, шаги воспроизведения, ожидаемый
и фактический результат. Для идеи опишите задачу пользователя и пример того,
как изменение поможет её решить. Обсудите крупную переработку до начала работы.

Об уязвимостях сообщайте приватно по [правилам безопасности](SECURITY.md).
Не размещайте ключи, пароли, куки, сессии и личные данные в issue или снимках.

## Подготовить pull request

1. Настройте окружение по [руководству разработчика](docs/development.md).
2. Создайте отдельную ветку и внесите небольшое связное изменение.
3. Добавьте или обновите проверку, если меняется поведение программы.
4. Выполните [Python- и frontend-проверки](docs/development.md#checks).
5. Опишите проблему, результат и фактически выполненные проверки в PR.
   Для видимых изменений приложите снимки на вымышленных данных.

Укажите связанные issues и ограничения проверки. Если какая-то проверка
не выполнялась, напишите об этом прямо. Не повышайте версию только ради
обычной правки; заметки к выпуску должны быть короткими и полезными пользователю.

## Ориентиры в коде

| Задача | Где искать |
| :--- | :--- |
| Обработка фотографий | `modules/uniq.py`, `web/src/features/uniq/` |
| Экраны приложения | `web/src/features/` |
| Запросы и типы API | `web/src/api/`, `modules/cloud.py`, `modules/remote.py` |
| Общие компоненты | `web/src/components/`, `web/src/hooks/`, `web/src/lib/` |
| Переводы | `web/src/lib/translations.ts` и локализованные подписи экранов |
| Стенд без реальных аккаунтов | `dev/_ui_mock.py` |

Используйте существующие компоненты Base UI и цветовые токены темы.
Проверяйте светлую и тёмную темы, узкий экран и управление с клавиатуры.
Подробные правила — в [документации интерфейса](web/README.md).

## Данные и совместимость

Используйте в тестах вымышленные аккаунты, куки и медиа. Не включайте
настоящие ключи API, сессии, пользовательскую папку данных и сетевые записи.
Реальные аккаунты TikTok в CI не используются.

Nimbus API — отдельный сервис. Клиент должен запускаться из чистого клона
без приватных серверных модулей. Сохраняйте совместимость API и показывайте
понятную ошибку, если сервер не поддерживает новую возможность.
